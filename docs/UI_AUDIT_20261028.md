# Revisión ampliada de interfaz de PeruSpatial Hub

Fecha: 28 de octubre de 2026. Complemento fuente 1.4.0, con correcciones
posteriores a la release de seguridad. Esta revisión prueba el panel, sus
eventos, las tareas de QGIS y el ZIP instalado en un perfil independiente.

## Correcciones verificadas

| Problema reproducido | Comportamiento corregido |
| --- | --- |
| Buscar el texto de las filas de ayuda expandía fuentes y provocaba peticiones remotas | Las ayudas no son resultados; el filtrado no dispara la carga remota al expandir visualmente el árbol |
| El filtro de categorías mantenía fuentes ajenas por sus filas de ayuda | Las ayudas heredan la visibilidad de su contenedor |
| Seleccionar carpetas junto con capas desactivaba la carga | El botón cuenta y carga solo las capas seleccionadas |
| Un clic repetido durante los eventos de carga duplicaba las capas | Se bloquea la reentrada y se desactiva la acción mientras carga |
| Reconstruir el árbol o descargar el complemento durante una carga causaba excepciones sobre objetos Qt eliminados | La carga conserva una copia de los datos seleccionados y comprueba la vida del panel antes de actualizarlo |
| Los errores de una carga parcialmente exitosa quedaban sin detalle | Se conservan las capas válidas y se muestran los errores de las restantes |
| La verificación de servidores podía ocultar el progreso de otra carga | Cada operación conserva su estado y la carga de capas tiene prioridad visual |
| Dos capas WMS de igual título se confundían como favoritas | La identidad incluye el servicio y el nombre técnico de la capa WMS |
| Un alias de la misma capa REST duplicaba el favorito | La identidad REST depende del recurso, no del título |
| Registrar conexiones escribía rutas antiguas que el navegador nativo no reconocía inmediatamente | Se usan las rutas nativas de configuración de QGIS 3.30+, compatibles con el mínimo declarado 3.34 |
| Registrar un nombre existente podía reemplazar otra URL o borrar su autenticación | Se conserva la conexión ajena, se resuelven colisiones de nombres y se mantiene authcfg salvo cambio explícito |
| Barras y diferencias de mayúsculas en nombres podían producir grupos anidados o colisiones en Windows | Se normalizan los nombres y se reserva el nombre existente sin distinguir mayúsculas |
| El menú contextual podía actuar sobre una fila previamente seleccionada | El clic sobre otra fila actualiza la selección; las acciones de un solo recurso se desactivan en selección múltiple |
| El aviso de datum se perdía al explorar carpetas remotas | La advertencia se propaga de la fuente a carpetas, servicios y capas |
| Configuraciones de autenticación JSON nulas o booleanas se convertían en identificadores ficticios | Se descartan valores que no son cadenas válidas |
| Los siete WMS de SENAMHI agotaban el tiempo de espera en Qt con HTTP/2 | Se utiliza HTTP/1.1 únicamente para HTTPS en idesep.senamhi.gob.pe/geoserver/, tanto en metadatos como en peticiones de los proveedores nativos |

## Pruebas locales

Entorno: Windows, QGIS 3.44.12, Qt 5.15.13 y Python de QGIS 3.12.13.
Las pruebas puras usan Python 3.11.9. Cada ejecución GUI crea un perfil,
configuración y directorio de autenticación separados en D:/DevResources.

- 73 pruebas puras: catálogo, URLs, WMS seguro, conexiones, compatibilidad de red, metadatos y ZIP.
- Ruff: sin errores.
- 30 pruebas con widgets Qt y tareas reales de QGIS: todas aprobadas, incluida la instalación y retirada de la compatibilidad de red.
- 10 comprobaciones dentro de QGIS completo con el paquete instalado:
  descubrimiento por el gestor de complementos, inicio, búsqueda, conexiones
  WMS/ArcGIS en el navegador, botón de carga, cierre y reapertura del panel,
  descarga y recarga del complemento, y ausencia de excepciones de slots Qt.
- El proceso de QGIS instalado termina con código 0 después de esas pruebas.
- Bandit sobre el contenido extraído del ZIP: nueve archivos Python,
  cero hallazgos, cero exclusiones y cero pruebas omitidas.
- El ZIP contiene 20 archivos e incluye los módulos de conexiones y compatibilidad de red.

Las pruebas de interacción usan capas de memoria para provocar fallos y cambios
de selección de forma controlada. La validación de proveedores externos se
ejecuta por separado con servicios reales.

Se revisaron capturas del panel de 330 píxeles, con fuente de 16 puntos,
con paleta oscura y dentro de la ventana principal de QGIS. Los controles
principales permanecieron dentro del área disponible.

La [ejecución final de integración continua](https://github.com/jordan-zav/Peruspatial-Hub/actions/runs/40749977900)
también aprobó las 73 pruebas puras, el escaneo del ZIP y las pruebas del
complemento instalado en Ubuntu 24.04 con QGIS 3.34.4: 30 casos de widgets,
10 comprobaciones de escritorio y salida con código 0. Las capturas y los
resultados JSON están en el artefacto qgis-interface-audit de esa ejecución.

## Incidentes del arnés de prueba

La primera ejecución de escritorio asumía que QGIS definía la variable de ruta
del script. Se corrigió el arranque para ejecutar el mismo archivo desde Python
y desde la opción de código de QGIS.

Otra versión inicial manipulaba directamente la población de elementos del
navegador nativo y produjo una caída al salir. Con el mismo complemento, la
prueba sin esa manipulación terminó correctamente. El arnés final expande la
vista nativa y usa el modelo Qt para leer sus filas; la instalación, descarga,
recarga y salida normal terminan correctamente. No se añadió al complemento
una evasión del cierre ni se ocultó la caída como una prueba aprobada.

## Servicios reales

Se cargaron cuatro casos con proveedores nativos: vector REST MIDAGRI,
MapServer MIDAGRI como ráster, WMS SENAMHI e ImageServer ASTER de INGEMMET.
La primera tanda produjo tres imágenes no uniformes sobre Perú sin errores de
renderizado. En una segunda tanda, el renderizado WMS de SENAMHI excedió el
límite de prueba de 30 segundos. Las dos observaciones se conservan.
Una reconsulta aislada posterior tampoco pudo crear el proveedor WMS de
SENAMHI como capa válida; el fallo queda registrado, sin cambiar la URL
oficial ni sustituirlo por un resultado simulado.

La investigación posterior comparó la misma petición en Qt: con HTTP/2
permitido expiró a los 10,17 segundos; con HTTP/2 desactivado obtuvo HTTP 200,
176.832 bytes y respuesta en 1,16 segundos. Un cliente independiente también
recibió HTTP 200. Por ello se añadió una regla acotada al GeoServer de SENAMHI,
manteniendo HTTPS, TLS y la validación de certificados.

La regla cubre metadatos y los proveedores nativos mediante un preprocesador
de QGIS 3.44 o posterior. Se instala una sola vez al activar el complemento y se retira al
descargarlo. Los demás hosts conservan su configuración HTTP/2. No se modifican
preferencias globales de QGIS ni se desactiva la validación TLS.

En QGIS 3.34 se reprodujo una caída al registrar el preprocesador de red,
coincidente con el [fallo de bindings Python registrado en QGIS](https://github.com/qgis/QGIS/issues/55329).
La versión final evita esa API antes de QGIS 3.44. Los metadatos mantienen la
compatibilidad HTTP/1.1 en todas las versiones admitidas; el ajuste del
proveedor WMS nativo de SENAMHI requiere QGIS 3.44 o posterior. Esta distinción
se comprueba en la prueba de ciclo de vida, en vez de invocar una API que puede
cerrar todo QGIS.

Después de la corrección, los siete WMS respondieron correctamente y el mapa
WMS volvió a renderizarse con 112 colores muestreados, sin errores. El
verificador real terminó con 26 de 27 fuentes disponibles: IDEP devolvió
HTTP 500 en esa tanda, aunque había respondido en la anterior. El diálogo de
resultados se abrió y cerró y el progreso volvió a su estado normal.
Estos resultados describen la disponibilidad observada, sin certificarla de
forma permanente ni justificar eliminar una institución del catálogo.

## Reproducción

Las pruebas de widgets se ejecutan con el Python de QGIS:

~~~text
python scripts/qgis_ui_checks.py --plugin-root RUTA_EXTRAIDA/peruspatial_hub --output SALIDA/widgets
~~~

La prueba de escritorio copia el complemento a un perfil nuevo y lo inicia
mediante el gestor real de QGIS:

~~~text
python scripts/qgis_desktop_checks.py --qgis-bin RUTA_A_QGIS --plugin-root RUTA_EXTRAIDA/peruspatial_hub --install --output SALIDA/desktop
~~~

Para comprobar las 27 fuentes mediante una tarea del panel:

~~~text
python scripts/qgis_ui_checks.py --plugin-root RUTA_EXTRAIDA/peruspatial_hub --live --case live_all_sources_health_action --output SALIDA/health
~~~

En Linux, la prueba de escritorio usa Xvfb y la plataforma Qt xcb. Las pruebas
de widgets usan la plataforma offscreen. El workflow prueba el ZIP generado y
conserva los resultados JSON, registros y capturas como artefactos de GitHub.

## Alcance y entrega

Se comprueba una muestra real de proveedores y las raíces de las 27 fuentes;
no se cargaron individualmente las más de 12.000 entradas del inventario.
La conservación de autenticación se prueba con identificadores de prueba,
sin cuentas privadas. Esta revisión no certifica QGIS 4 ni todas las variantes
de macOS y Linux.

La creación de una capa con un proveedor nativo aún puede esperar su respuesta
de red; la protección de vida del panel no convierte la construcción de cada
proveedor en una operación asíncrona.

Las correcciones se guardan en la rama principal. Se prepara un ZIP local
identificado como revisión de interfaz; esta auditoría no vuelve a mover el
tag publicado 1.4.0. El portal de QGIS requiere una versión numérica nueva
para reemplazar la entrega bloqueada.
