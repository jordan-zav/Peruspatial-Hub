# Auditoría de PeruSpatial Hub — 28 de octubre de 2026

Nota posterior: el portal QGIS bloqueó el ZIP original por el uso de ElementTree.
La release GitHub 1.4.0 fue reemitida con la
[corrección de seguridad XML](SECURITY_XML_20261028.md), 51 pruebas y escaneo
Bandit del ZIP. Los resultados de 37 pruebas descritos abajo corresponden a
la auditoría original, anterior a esa corrección.

## Resultado y alcance

Fuente preparada como versión 1.4.0. Revisión del catálogo, descubrimiento REST,
lector WMS, búsqueda local, favoritos, recarga, carga nativa y empaquetado.
Las comprobaciones de interfaz y proveedores se ejecutaron con QGIS 3.44.12
real y configuración de prueba aislada. No se modificó el perfil habitual de QGIS.
Esta auditoría no publica una release ni certifica todas las capas de terceros.

## Catálogo

| Indicador | Anterior | Actualizado |
| --- | ---: | ---: |
| Fuentes configuradas | 14 | 27 |
| Entradas únicas | 8.059 | 12.396 |
| Entradas conservadas sin nueva verificación | No se distinguían | 50 |

Las entradas incluyen directorios de servicio y capas; no son 12.396 datasets
independientes. Se incorporaron 13 endpoints oficiales: ANA/SNIRH,
CENEPRED/SIGRID, MTC/Provías Nacional, MIDAGRI, dos directorios SENACE y siete
WMS temáticos de SENAMHI. Se añadieron categorías de agricultura/catastro y
transporte/infraestructura.

El descubrimiento consulta el directorio y los metadatos de cada servicio
encontrado. Las entradas repetidas se deduplican. Los fallos parciales no borran
las entradas anteriores: se conservan marcadas como sin verificar, con la fecha
de referencia. Una actualización completa y correcta sí puede retirar entradas
que el servidor ya no publica.

## Disponibilidad externa

Los 27 endpoints respondieron correctamente al menos una vez durante la
auditoría. En la comprobación final, 26 respondieron y el WMS de sectores
climáticos de SENAMHI agotó el plazo; se considera intermitente, no una baja
permanente. La salud del endpoint y el estado de todas sus ramas son cosas
distintas.

El inventario registra 21 fuentes sin errores de descubrimiento y seis con
ramas parciales: ANA, INGEMMET general, Provías, OEFA, OSINERGMIN y SERFOR.
Se observaron solicitudes de token, servicios retirados y algunos timeouts.
Las 50 entradas retenidas pertenecen a OSINERGMIN (35) y SERFOR (15).
No se intentó acceder a datos protegidos ni se desactivó TLS.

Los endpoints INEI probados agotaron el plazo; el endpoint COFOPRI evaluado
presentó un problema de cadena TLS. El catálogo general SENAMHI también agotó
el plazo, pero sus siete accesos temáticos se verificaron e incorporaron.
Estos resultados describen esta estación y este momento, no una disponibilidad
universal. No se afirma que no existan otros servicios públicos que puedan
incorporarse en revisiones futuras.

## Errores corregidos

1. El lector WMS llamaba a un método de QString sobre una cadena Python.
   Se reprodujo con QGIS/PyQt5 real. Ahora el panel y el generador comparten
   un lector independiente de Qt, con comprobación de protocolo y capas con nombre.
2. Las URI WMS se entregaban al proveedor con la codificación incorrecta.
   La misma capa falló antes del cambio y cargó después al usar la URI codificada.
3. Los CRS propios de una capa reemplazaban los heredados. Ahora los amplían.
   También se interpretan listas SRS de WMS 1.1 y parámetros sin distinción de caja.
4. Se perdían parámetros de proveedor como map al construir una conexión WMS.
5. La verificación WMS aceptaba cualquier respuesta HTTP correcta. Ahora valida
   GetCapabilities y un catálogo importable.
6. Una respuesta antigua podía sobrescribir una recarga reciente. Cada petición
   tiene una generación y se ignoran las respuestas que ya no corresponden.
7. Inventarios y favoritos malformados podían provocar excepciones de interfaz.
8. El generador podía perder el inventario anterior por fallos remotos. Ahora
   conserva entradas afectadas, permite actualizar fuentes concretas y escribe
   el resultado mediante sustitución atómica.
9. La prueba de documentación esperaba una frase española en el README inglés.
   Ahora comprueba la versión de metadata frente al badge de ambos idiomas.
10. La guía de inicio remitía al menú Base de datos, pero el controlador registra
    el acceso en Complementos. Se corrigió la ruta de ambos README.

## Validación

- La suite inicial tenía 11 pruebas aprobadas y una fallida.
- La suite actual tiene 37 pruebas aprobadas, incluida la integridad y contenido del ZIP.
- El ZIP se extrajo en una carpeta nueva y se probó desde esa copia con QGIS real,
  incluidos inicio, apertura, descarga, proveedores y los tres renderizados nativos.
- Las regresiones incluyen XML WMS, CRS heredados, parámetros de URL, fuentes,
  inventarios malformados y preservación de entradas ante fallos parciales.
- QGIS real: 27 fuentes visibles, búsqueda local, favoritos, recargas fuera de
  orden, respuesta después de eliminar un elemento y cancelación al descargar.
- Inicio, apertura y descarga del controlador completo del plugin; configuración
  de autenticación conservada en la URI genérica, sin utilizar credenciales reales.
- Proveedores reales: vector REST MIDAGRI, ráster MapServer MIDAGRI,
  WMS SENAMHI e ImageServer ASTER DEM de INGEMMET.
- Renderizados nativos de los tres rásteres sobre Perú, a 640 × 480 píxeles:
  imágenes no uniformes y sin errores del renderizador en la muestra verificada.

Los renderizados y las muestras de carga no verifican exhaustivamente todas
las subcapas, permisos, descargas de entidades o escalas. Tampoco validan la
exactitud temática de los datos de las instituciones.
La ejecución real corresponde a QGIS 3.44.12/Qt5; no se ejecutó una matriz de
versiones antiguas ni una sesión QGIS/Qt6. La importación de QAction admite
las ubicaciones de ambas generaciones de Qt.

## Mantenimiento reproducible

Desde una copia del repositorio, con las dependencias de desarrollo instaladas:

~~~text
python -m pytest -q
python scripts/audit_services.py --output audit.json
python scripts/build_catalog.py --previous catalog/catalog.json --output catalog/catalog.json
python scripts/build_catalog.py --source SENACE --previous catalog/catalog.json --output catalog/catalog.json
python scripts/package_plugin.py --outdir RUTA_DE_SALIDA --no-legacy
~~~

La opción no-legacy evita modificar el ZIP de compatibilidad en dist.
El controlador scripts/qgis_smoke.py admite output, live y plugin-root para
repetir la comprobación con QGIS real y con un ZIP extraído en otra carpeta.
En Windows debe ejecutarse con el intérprete preparado por python-qgis-ltr.bat,
no con un Python ordinario. La comprobación aborta si la configuración QGIS
no queda dentro de la carpeta de salida indicada.
